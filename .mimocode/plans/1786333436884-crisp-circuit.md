# 专家建议实施计划

## 改动概要

| # | 建议 | 改动 |

| 1 | 移除 coerceIn，恢复 Int (32-bit) 编码 | ShakeRandomGenerator + EntropyEstimator |
| 2 | SHA-512(池‖盐) → HKDF-HMAC-SHA512 | ShakeRandomGenerator.onCompleteInternal |
| 3 | 增加可预测性测试（线性复杂度/压缩率） | EntropyEstimator 新增 predictabilityScore |

## 改动 1：恢复 Int 编码

**文件**: `utils/ShakeRandomGenerator.kt`, `utils/EntropyEstimator.kt`

### ShakeRandomGenerator

```kotlin
// 之前: coerceIn + toShort
val qdx = (dx * 1000).roundToInt().coerceIn(Short.MIN_VALUE, Short.MAX_VALUE).toShort()

// 之后: 直接 Int，不截断
val qdx = (dx * 1000).roundToInt()
```

- 熵池存储改回 4 字节 Int × 3 轴 = 12 字节/样本
- `onSensorData` 回调签名不变（已经是 Int）
- `ByteBuffer.allocate(12).putInt(qdx).putInt(qdy).putInt(qdz)`

### EntropyEstimator

- `feed(dx: Int, dy: Int, dz: Int)` 参数类型恢复 Int
- 位计数器从 16 改回 32 位
- 直方图仍按字节统计（256 桶），但统计的是 12 字节而非 6 字节
- `totalSamples += 3`，位计数 `countBits` 每个 Int 的 32 位

> 理由：最终输出经过 SHA-512/HKDF，输入空间的基数（而非字节分布均匀性）才是抵抗暴力破解的核心。高位 0/FF 不影响安全性。

## 改动 2：HKDF 替代 SHA-512

**文件**: `utils/ShakeRandomGenerator.kt`, 新建 `utils/HkdfSha512.kt`

### 新建 HkdfSha512.kt

手动实现 RFC 5869 HKDF，基于 `javax.crypto.Mac` + `HmacSHA512`：

```kotlin
object HkdfSha512 {
    // Extract: PRK = HMAC-SHA512(salt, IKM)
    // Expand:  OKM = HMAC-SHA512(PRK, info || 0x01) 取前 L 字节
    
    fun extract(salt: ByteArray, ikm: ByteArray): ByteArray
    fun expand(prk: ByteArray, info: ByteArray, length: Int): ByteArray
    fun derive(salt: ByteArray, ikm: ByteArray, info: ByteArray, length: Int): ByteArray
}
```

### ShakeRandomGenerator.onCompleteInternal

```kotlin
// 之前:
val digest = MessageDigest.getInstance("SHA-512")
digest.update(collectedBytes.toByteArray())
digest.update(saltBuf)
val hash = digest.digest()

// 之后:
val systemSalt = ByteArray(32).also { java.security.SecureRandom().nextBytes(it) }
val info = "ShakeRandomGenerator".toByteArray()
val okm = HkdfSha512.derive(
    salt = systemSalt,
    ikm = collectedBytes.toByteArray(),
    info = info,
    length = 32
)
val hexValue = okm.joinToString("") { "%02X".format(it) }
```

- `salt`: SecureRandom 生成 32 字节系统熵（每次独立，不存储）
- `ikm`: 熵池原始字节
- `info`: 上下文绑定字符串，防止跨用途密钥复用
- 输出: 32 字节 (256-bit)

## 改动 3：可预测性测试

**文件**: `utils/EntropyEstimator.kt`

### 原理

用简化的压缩率测试检测周期性运动：对熵池数据做游程编码（RLE），压缩比越高说明数据越有规律。

### 实现

```kotlin
// 在 entropyScore 计算中加入
val compressionRatio: Double
    get() {
        // 对最近 N 字节做 RLE，计算压缩比
        // 压缩比 = 原始大小 / 压缩后大小
        // 1.0 = 完全随机不可压缩，越高 = 越有规律
    }
```

- `predictabilityScore = (1.0 - (compressionRatio - 1.0) / threshold).coerceIn(0.0, 1.0)`
- 综合评分加入可预测性权重:

```kotlin
// 之前:
entropyScore = shannonRatio * 70 + balanceScore * 30

// 之后:
entropyScore = shannonRatio * 50 + balanceScore * 20 + predictabilityScore * 30
```

- 需要维护一个环形缓冲区存储最近的原始字节（如最近 256 字节）
- 每次 feed 时更新 RLE 压缩比
